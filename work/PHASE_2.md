# Phase 2 — builds

Legend: VALUE | script + output + commit | STATUS (VERIFIED / MANUAL / UNVERIFIED)

Working document, appended as each hypothesis finishes and committed
incrementally (not batched to the end), per the standing rules.

Three builds run for this phase, sequenced to avoid three concurrent
`cargo build` jobs saturating the same 16-core machine:

1. **2.1** (`run_h2_1_build.sh` / `h2_1_cgu16_all43.py`) — the 43-crate
   codegen-units=16 rebuild. Calls `bench/rulemine/build_v3.sh`
   **unmodified**, given all 43 crate names instead of the 20 it already
   had, so it only builds the 23 missing ones (idempotent). This is the
   single most important item in the whole task list per the brief.
2. **2.2** (`h2_2_build_inline_suppressed.sh` / `h2_2_analyze.py`) — a
   12-crate subset at opt-z with LLVM inlining suppressed
   (`-Z inline-llvm=no`, checked against this exact toolchain — see the
   build script's header for why this flag beats the task's own fallback
   suggestions here).
3. **2.3** (`h2_3_build_cgu_sweep.sh` / `h2_3_analyze.py`) — the two cgu
   sweep points (4, 256) at lto=thin that neither the main corpus nor V3
   already has, on the same 12-crate subset, completing a clean
   {1,4,16,256} curve.

All output regenerated by these scripts is gitignored derived data
(`bench/rulemine/v3/fde/`, or new directories under `bench/hypotheses/`),
matching this study's own convention that build products don't belong in
git — only the scripts and the numeric results below are committed.
